# Отчёт: функциональное тестирование embedded-candidate-v1

## Паспорт версии и запуска

- Объект: функция `candidate(items, promo, fulfillment)` в `lab.py`, версия **embedded-candidate-v1**.
- Среда: Python 3.10+, стандартная библиотека, сеть не требуется.
- Команда прогона: `python runner.py > evidence/run.log` (Windows: та же команда в PowerShell).
- Команда одиночного случая: `python lab.py > evidence/C00.txt`.
- Источник ожиданий: правила R-QTY, R-PROMO, R-DISCOUNT, R-DELIVERY, R-TOTAL из Задания (снимок карточки 24.10.2026). Кандидат **не является эталоном** — ожидания рассчитаны по правилам.
- Каталог `DATA` в `lab.py` совпадает с таблицей задания (8 товаров).
- Ограничение варианта: нет reference, нет R-SORT, нет UI/API/БД/платежей. ZERO×1 вынесен во вторую пару.

## Область

**Включено:** валидация количества и остатка, нормализация промокода, скидка и округление, стоимость доставки и самовывоз, итог `total`, повторный расчёт.

**Исключено:** R-SORT (отсутствует в embedded-варианте), reference (отсутствует), HTTP/UI/БД/авторизация/платежи, производительность и p95, полный пакет из 12 товаров.

## Дефекты (3 подтверждённых)

### BUG-1. Не проверяется остаток (R-QTY)

- **Шаги:** `candidate({"S2": 3}, "", "delivery")` и `candidate({"ZERO": 1}, "", "pickup")`.
- **Ожидание:** ошибка `QUANTITY` — 3 > остатка 2; 1 > остатка 0.
- **Факт:** расчёт выполняется (S2×3 → total 74900; ZERO×1 → total 90000).
- **Влияние:** продажа сверх остатка, завышенные суммы; нулевой остаток не отсекается.
- **Воспроизведение:** стабильно, C09; во второй паре — ZERO×1.
- **Гипотеза причины:** в цикле проверяется только `1 <= q <= 10`, `stock` из `DATA` читается, но не сравнивается с `q`.

### BUG-2. Округление скидки floor вместо half-up (R-DISCOUNT)

- **Шаги:** `candidate({"E10005": 1}, "STUDY10", "delivery")`.
- **Ожидание:** `discount=(10005+5)//10=1001`, `after=9004`, `total=38904`.
- **Факт:** `discount=10005//10=1000`, `after=9005`, `total=38905`.
- **Влияние:** −1 копейка на каждый eligible-товар с дробной скидкой; накапливается в смешанных корзинах (C07).
- **Воспроизведение:** стабильно, C06/C06R/C07.
- **Гипотеза причины:** `eligible // 10` вместо `(eligible + 5) // 10`.

### BUG-3. Порог доставки при равенстве 300000 (R-DELIVERY)

- **Шаги:** `candidate({"B3000": 1}, "", "delivery")`.
- **Ожидание:** `after=300000`, равенство → `delivery=0`, `total=300000`.
- **Факт:** `delivery=29900`, `total=329900`.
- **Влияние:** переплата 29900 коп. ровно на границе. C03 (ниже порога) и C04 (выше) корректны.
- **Воспроизведение:** стабильно, C01/C01R.
- **Гипотеза причины:** `after_discount > 300000` вместо «при равенстве и выше → 0» (т.е. `after_discount >= 300000`).

- Модель: указана в `evidence/ai/response.txt`, дата 2026-10-24.
- Запрос: `evidence/ai/prompt.txt`.
- Ответ: `evidence/ai/response.txt`.
- Проверены три утверждения **учебного ответа** из задания.

| Утверждение (учебный ответ) | Ответ ИИ | Моё решение | Проверка по правилам |
|---|---|---|---|
| «У E3000 со STUDY10 доставка бесплатна, потому что исходная сумма 300000» | Нет, доставка 29900; порог считается после скидки (270000 < 300000) | Принял (ИИ прав); учебное утверждение **отклонил** | R-DELIVERY: 300000−30000=270000 < 300000 → 29900, total 299900 (C05) |
| «Для E10005 со STUDY10 скидка 1000 коп.» | Нет, 1001 коп., half-up: (10005+5)//10 = 1001 | Принял (ИИ прав); учебное утверждение **отклонил** | R-DISCOUNT: 1001 коп., after 9004, total 38904 (C06) |
| «Код действует 30 дней» | Срок в правилах не задан | Принял (ИИ прав); учебное утверждение **отклонил** | В R-PROMO срока нет; выдумывать нельзя |

Итог: ИИ дал корректные ответы на все три утверждения и сам указал, что порог доставки считается после скидки. Учебный ответ из задания содержит три ошибки — все отклонены. Код кандидата, тем не менее, реализует ту же ошибку, что в учебном ответе (floor вместо half-up), — это и есть BUG-2.

### Правка документа (до / после / причина)

**До:**
- C06 ожидание: `discount = 1000 коп.` — сверял с выводом `lab.py`.

**После:**
- C06 ожидание: `discount = 1001 коп.` — по формуле R-DISCOUNT `(eligible_subtotal + 5) // 10`.

**Причина:** `lab.py` реализует `eligible // 10` (floor) и даёт 1000; правило требует half-up и даёт 1001. Ответ ИИ и независимый расчёт подтверждают 1001. Оракул строится по правилам, а не по коду кандидата. Ответ ИИ совпал с правилом и не совпал с кандидатом — дополнительное подтверждение BUG-2.

## Заключение

Проверено 10 случаев первой пары на embedded-candidate-v1 (Python 3.10+, stdlib, офлайн). Покрыты: порог доставки и два соседних значения (C01/C03/C04), eligible-товар со скидкой (C05), округление на E10005 (C06), смешанная корзина E10005+N200 (C07), допустимый остаток S2×2 (C08), превышение S2×3 (C09), самовывоз (C02, C10). Два случая (C01, C06) повторены — результаты воспроизводимы.

Совпало с правилами: нормализация промокода, отклонение неизвестного кода, отклонение bool/дроби/нуля, скидка на E3000 (C05), самовывоз (C02, C10), значения ниже и выше порога доставки (C03, C04), допустимый остаток S2×2 (C08).

Нарушено (3 подтверждённых дефекта): (1) не проверяется остаток — S2×3 и ZERO×1 принимаются (R-QTY); (2) скидка округляется вниз вместо half-up — E10005 даёт 1000 вместо 1001 (R-DISCOUNT); (3) при `after_discount` ровно 300000 доставка 29900 вместо 0 (R-DELIVERY). Все три воспроизведены и имеют доказательства в `evidence/`.

Неизвестно / не проверено: R-SORT (нет в embedded-варианте), reference (отсутствует), поведение на полном 12-товарном пакете, HTTP/UI/платежи (вне области).

Рекомендация: версию embedded-candidate-v1 **нельзя считать пригодной** по денежным правилам — три дефекта затрагивают R-QTY, R-DISCOUNT, R-DELIVERY. После исправления (сравнение `q` с `stock`; `(eligible+5)//10`; `after_discount >= 300000`) требуется повторный прогон C01, C06, C07, C09 и ZERO×1 во второй паре. Вывод ограничен CLI-функцией и не переносится на UI, API или нагрузку.
