Минимальный автономный запуск без архива

Сохраните код в lab.py. Команда python lab.py запустит один пример. Меняйте только переменные items, promo, fulfillment в самом низу, сохраняя каждую комбинацию в отчёте. Для сохранения вывода: python lab.py > evidence_C01.txt. Python3.10+ и стандартная библиотека, внешние пакеты не нужны. Это учебный кандидат; его поведение требуется исследовать, а не принимать за эталон.

import json
DATA = {
    "B3000": (300000, 10, False), "E3000": (300000, 10, True),
    "E10005": (10005, 10, True), "N200": (20000, 10, False),
    "LOW": (299999, 10, False), "HIGH": (300001, 10, False),
    "S2": (15000, 2, True), "ZERO": (90000, 0, True)
}
def candidate(items, promo, fulfillment):
    if not isinstance(promo, str):
        return {"error": "PROMO"}
    code = promo.strip().upper()
    if code not in ("", "STUDY10"):
        return {"error": "PROMO"}
    if fulfillment not in ("delivery", "pickup"):
        return {"error": "FULFILLMENT"}
    if not items:
        return {"error": "EMPTY_CART"}
    subtotal = eligible = 0
    for product_id, q in items.items():
        if product_id not in DATA:
            return {"error": "PRODUCT"}
        if type(q) is not int or not 1 <= q <= 10:
            return {"error": "QUANTITY"}
        price, stock, participates = DATA[product_id]
        subtotal += price * q
        if participates:
            eligible += price * q
    discount = eligible // 10 if code else 0
    after_discount = subtotal - discount
    delivery = 0 if fulfillment == "pickup" or after_discount > 300000 else 29900
    return {"subtotal": subtotal, "eligible_subtotal": eligible,
            "discount": discount, "after_discount": after_discount,
            "delivery": delivery, "total": after_discount + delivery}
items = {"B3000": 1}
promo = ""
fulfillment = "delivery"
print(json.dumps({"version": "embedded-candidate-v1", "input": {
    "items": items, "promo": promo, "fulfillment": fulfillment},
    "actual": candidate(items, promo, fulfillment)}, ensure_ascii=False, indent=2))

Сброс не нужен: каждый запуск начинает новый расчёт, данные не сохраняются. Этот вариант не имеет интерфейса и сортировки. Если полного пакета нет, вместо сортировки во второй паре добавьте проверку ZERO×1; ограничение явно укажите. Встроенный вариант и пакет имеют одинаковые правила и сопоставимые ошибки расчёта, но разные идентификаторы версии.

Обязательные артефакты
Паспорт версии и запуска: 5–8 строк.
Таблица не менее 8 случаев в первой паре и 12 в полном варианте: ID, правило, вход, ожидание, факт, статус, доказательство.
До трёх развёрнутых сообщений о подтверждённых расхождениях: шаги, ожидание, факт, влияние, воспроизведение.
Заключение 150–250 слов с ограничениями и рекомендацией.
Проверка ИИ/учебного ответа и одно доказанное улучшение документа.
Единые исходные данные

Это синтетическая учебная система. Реальных денег, оплат, писем и доставки нет. Публичный адрес магазина не нужен для выполнения. Если преподаватель отдельно выдаст веб-стенд, сначала проверьте соответствие его версии этим правилам; результаты разных версий не смешивайте.

R-QTY: количество целое от 1 до 10, суммарно по одному товару не больше остатка. Ноль, дробь, bool и превышение отклоняются. Расчёт корзины не списывает остатки.
R-PROMO: пробелы по краям кода удаляются, регистр не учитывается. Пустой код означает отсутствие скидки. Допустим только STUDY10; неизвестный код отклоняется.
R-DISCOUNT: STUDY10 применяется один раз к общей стоимости товаров eligible=true. Скидка 10%, округление half-up до копейки: (eligible_subtotal+5)//10. Минимальной суммы для скидки нет. Неакционные товары остаются по полной цене.
R-DELIVERY: доставка стоит 29900 коп., если сумма товаров после скидки меньше 300000 коп.; при равенстве и выше доставка 0. Самовывоз всегда 0.
R-TOTAL: total=subtotal-discount+delivery. Деньги целые копейки. Повторный расчёт из исходных данных не накапливает скидку.
R-SORT: сортировка цены числовая по возрастанию; при равной цене id по возрастанию.

Для всех работ достаточно этой части каталога; полный автономный пакет содержит 12 товаров:

id	Цена, коп.	Остаток	eligible
B3000	300000	10	false
E3000	300000	10	true
E10005	10005	10	true
N200	20000	10	false
LOW	299999	10	false
HIGH	300001	10	false
S2	15000	2	true
ZERO	90000	0	true

Проверенный пример: E3000×1, STUDY10, delivery → subtotal=300000, discount=30000, after_discount=270000, delivery=29900, total=299900. Это пример формата расчёта; остальные ожидания вычислите самостоятельно.

Сдача и проверка самостоятельности

Выберите равноправный формат:

Markdown: report.md и папки data/ и evidence/ в ZIP. Таблицы можно оставить в Markdown или CSV. Код, если использовался, приложите отдельным файлом.
Git-репозиторий: README.md с инструкцией, report.md, data/, evidence/ и при наличии tests/. Ссылка должна открываться преподавателю; публичный доступ не обязателен. При отсутствии доступа сдайте ZIP репозитория или экспорт файлов.

Формат не добавляет и не снимает баллы. Укажите версию требований, источники ожиданий, реальные команды и фактические результаты. Не подделывайте запуск, скриншоты или найденные дефекты. Если среда недоступна, обозначьте конкретный блокер и продолжайте анализ, который от неё не зависит.

Git можно использовать и для Markdown-сдачи: сохраните исходный вариант и исправленную версию двумя осмысленными коммитами; в report.md приведите короткий diff или таблицу изменений. При отсутствии Git достаточно той же таблицы «до/после/причина»: оценивается проверяемое изменение, а не установленный инструмент.

Для ИИ передавайте только синтетические данные задания. Сохраните один запрос, существенный фрагмент ответа и таблицу «принял/исправил/отклонил + проверка». Если ИИ недоступен, разберите предоставленный ниже учебный ответ по тем же правилам. Платная подписка не нужна. На защите преподаватель выбирает один расчёт или вывод и просит объяснить его без подсказки.

Учебный ответ для проверки: «У E3000 со STUDY10 доставка бесплатна, потому что исходная сумма 300000. Для E10005 со STUDY10 скидка 1000 коп. Код действует 30 дней». Проверьте каждое утверждение по исходным правилам; отсутствие срока действия в требованиях не разрешает его выдумывать.
